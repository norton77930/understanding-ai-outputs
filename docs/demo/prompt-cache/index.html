Claude Code · prompt caching · compaction

Every turn re-sends the whole conversation. The cache makes that cheap, until it expires.

The model remembers nothing between requests. So Claude Code sends the full context on every turn. Prompt caching reads the unchanged beginning from a cache at a fraction of the price. After a break longer than the cache lifetime, the whole history is processed again at full price.

01Each request contains everything, but only the newest part is fully processed

Each request has the system prompt, your project context, and every prior message and tool result. The unchanged beginning is the prefix. The cache supplies the prefix. Only the newest exchange is new input.

03The cache expires after inactivity: one hour on a subscription, five minutes otherwise

Every request that hits the cache resets the timer. A break longer than the lifetime lets the cache expire. Then the first request after the break reprocesses the whole history. That is slower and costs more.

04Near the context limit, Claude Code compacts the history into a summary

The conversation grows until it approaches the limit of the context window. Then Claude Code compacts it automatically. The summary replaces the message history, the same as a manual /compact.

05An automatic handoff lets you decide what survives

The handoff replaces the automatic pass with a summary that you design. Step through it.

  1. The conversation reaches a threshold that you choose.
  2. The handoff waits for a natural break.
  3. It writes a structured summary.
  4. It clears the conversation.
  5. It continues in a fresh conversation, from the summary.

06Keeping the cache warm pays off only for long sessions and short breaks

While you are away, a tiny request goes out shortly before the cache expires. It reads the conversation from the cache and resets the timer. Each refresh is billed as a cache read of the whole conversation. So many refreshes can cost more than one full reprocess.

✓Summary

  • Claude Code re-sends the full context on every turn, because the model remembers nothing.
  • The cached prefix costs 0.1× (0.05× on Opus 5.5 and Sonnet 5.5). Only the newest exchange costs full price.
  • The cache expires after 1 hour (subscription, within plan usage) or 5 minutes (API key, cloud provider, usage credits). Each cache hit resets the timer.
  • After the cache expires, the next turn reprocesses the whole history. It is slower and costs more.
  • Automatic compaction replaces the history with a summary. Compact at natural breaks while the cache is warm. Run /clear between unrelated tasks.
  • An automatic handoff writes your own summary (verified, failed, next step), clears and continues.
  • Keeping the cache warm pays off only for long sessions and breaks not much longer than the cache lifetime.
